# Phase 7 web report screen — 21 October 2026

The private finance report page at `/finance/reports` now lets an active President, Vice President, Secretary or Treasurer request a fixed month, year or bounded date-range snapshot. An active System Admin can open an existing report ID. The screen displays account totals in exact paise and up to 100 source lines; the server's private CSV route pages the full report and checks ledger reconciliation. The browser hashes downloaded bytes with SHA-256 and compares them with the server digest before saving. It never writes the access token into a URL or persistent storage.

The page first reads `/api/management/report-capabilities`, a no-store server response whose `exportsApproved` value is true only when `REPORT_EXPORTS_APPROVED=true`. Report actions recheck this endpoint. The default remains false in `.env.example`; the named masjid privacy/publication signatory has not approved production report fields. The CSV route independently rejects downloads when the flag is off and validates the issued Auth user, live role and identity gate when on. Database report RPCs have their own role guards; the approval flag is a web publication control, not a database permission.

**Checks:** four new focused Node tests cover calendar validation, exact large/negative paise, digest mismatch, UUID validation and capability fail-closed behavior. All 104 Node tests, ESLint, TypeScript typecheck, Prettier and Next production build passed. A temporary production server on `127.0.0.1:18090` returned HTTP 200 for the page, `{exportsApproved:false}` with `Cache-Control:no-store` and 503 from CSV while off. The in-app browser showed the approval message. A separate temporary server with the flag true returned `{exportsApproved:true}` with no-store; without Supabase environment variables, the browser showed an unavailable state. Both temporary servers were stopped.

The previously completed disposable local issued-session CSV HTTP test remains the backend proof. A subsequent signed-in browser check used the reproducible `backend/scripts/phase7_report_browser_fixture.mjs` fixture against the empty named `masjid-e-mamoor-2-fresh` stack. It created three synthetic roles and one cash account with a verified 12,345-paise opening. The flag was true only for the temporary local web process.
