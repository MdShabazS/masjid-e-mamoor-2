# Android meeting invitations — 26 October 2026

The signed-in Android screen now lists only meetings returned by `list_visible_committee_meetings`: meetings created by this actor or addressed to this actor. President, Vice President, Secretary and Data Entry can schedule a future meeting; its date and time are validated in India time before calling the guarded RPC. The organizer can invite a member by account ID and cancel with a recorded reason after a confirmation prompt. An invitee can accept or decline a still-active, future meeting; a decline reason is optional. Mutations preserve an operation ID on a same-input retry. A saved response stays visible if the follow-up list refresh fails. Meeting times render in India time.

This adds the scheduling and invitation workflow only. No Android location check-in, attendance mark, private memo image, meeting edit or push reminder is enabled by this client change. Those features require the confirmed site, policy and field evidence in the Phase 9 task list. The existing database functions validate role, invitation owner, active status and start time and deny direct table access to clients.

Verification: 162 Node tests, including two new India-time and invalid-date input checks, lint, typecheck, format and Android bundle export passed. The existing Phase 9 rollback-only SQL fixture and hosted role-denial matrix cover the protected meeting RPCs. A signed-in Android device journey and staging create/invite/RSVP/cancel retry test remain open.
