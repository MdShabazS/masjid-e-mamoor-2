# Android President payment QR profile

**Date:** 24 October 2026 (India time). The Android app now renders a President-only payment QR profile section after the database identity gate and role load. It lists active bank/UPI accounts, lets the President choose a PNG/JPEG from the system image picker, previews it, requires payee confirmation, and submits it to the same authenticated web API used by the web profile. The operator can privately load the current QR and version. A stable operation ID is reused on uncertain retries and reset when the image or account changes. Server validation, digest verification and database President-only activation remain authoritative.

The selected file is limited to PNG/JPEG and 5 MiB at the client when size metadata is available; the server enforces the byte, decoded-image and digest limits regardless of client metadata. The native picker uses the SDK 57 compatible `expo-image-picker@57.0.20`. Its app plugin disables camera and microphone permission because this workflow only needs the system library picker.

**Verification:** clean `npm ci`, 131 Node tests, lint, typecheck, formatting check, web build and Android bundle export passed. Expo config introspection passed. A regenerated native Android project compiled `assembleDebug` and `assembleRelease` with JDK 21. The debug APK at `apps/android/android/app/build/outputs/apk/debug/app-debug.apk` is 140,144,461 bytes with SHA-256 `d6683e856667e6a6eccfec40f644d364a7b135bccde4385865814f5c5079a46f`. The release-variant APK is 70,697,032 bytes with SHA-256 `30af351786ea0d6ecbe0a994b9d5c3c6713f80308ce9cfdffebbee5e84f3233f`. Its package ID is `org.masjidemamoor.app.fresh`, version 0.1.0 (code 1), and it is signed with `CN=Android Debug` (certificate SHA-256 `fac61745dc0903786fb9ede62a962b399f7348f0bb6f899b8332667591033b9c`), so it is **not a publishable release**. APK inspection found Internet and legacy storage permissions, with no camera or microphone permission. `npm audit --audit-level=critical` passed but reports five high advisories in Expo CLI/code-signing dependencies (node-forge and zod); these remain a release review item.

**Still open:** configure the real package identity and release signing; install on a real Android device; test replacement, retry/conflict and sign-out on that device with separately issued sessions; compare the selected QR payee with the official bank record. This synthetic emulator result does not establish field acceptance or real-money readiness.

**Emulator smoke, 24 October:** the new release-variant APK installed with `adb install -r` and cold-launched without Metro on the existing Pixel 8 Android 36 emulator. `MainActivity` remained foreground, and the recent React Native/Android runtime error log was empty. The rendered screen correctly stated that the Supabase connection was not configured. This APK intentionally has no development or production endpoint baked in, so it did not reach sign-in or the President QR section. The local Docker/Supabase stack was unavailable (`/var/run/docker.sock` absent), and there is no Android environment file; an authenticated QR journey still needs a matching test backend and web API URL.

**Signed-in emulator journey, later on 24 October:** Colima and an isolated local Supabase stack were started with two synthetic Auth users, one synthetic UPI account and a PNG with a matching synthetic payee. A separate test-only APK pointed to the local Supabase and web API endpoints through `adb reverse`; its ignored native manifest temporarily allowed cleartext localhost traffic. The President signed in, selected the account, saw the no-current-QR state, used the system photo picker and preview, and could activate only after checking payee confirmation. The first activation exposed a real bug: Expo's multipart encoder rejected React Native's `{ uri, name, type }` FormData part with `Unsupported FormDataPart implementation`. The app now wraps the selected URI in Expo FileSystem's `File` before upload and rechecks its size. A rebuilt test APK activated successfully, and the private current-image view rendered the active image. Direct database verification showed two test users, one QR version and one Storage object. The President signed out; the Treasurer signed in and had no President profile QR controls. A disposable database reset returned Auth, QR and Storage counts to `0|0|0`. The test APK was uninstalled and removed, the synthetic photo deleted, the temporary manifest restored, and the local services stopped.

After the FileSystem fix, clean `npm ci`, all 131 Node tests, lint, typecheck, formatting and Android bundle export passed. The local test used no real payee or production service. Real bank verification, replacement/retry on device, real-device acceptance, release signing and production configuration remain open.
